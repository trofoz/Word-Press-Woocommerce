## Цільова матриця

Інженерна база: PHP 8.3+, WordPress 6.9+, WooCommerce 10.8+, InnoDB, MySQL 8.0+ або MariaDB 10.6+, HTTPS. Це вибраний мінімум форка, а не твердження про мінімум upstream.
Підстава: [офіційні рекомендації WooCommerce](https://woocommerce.com/document/server-requirements/), прочитані 10.10.2026.

| Контур | Версії / режими | Призначення |
|---|---|---|
| Мінімальний | PHP 8.3, WP 6.9, WC 10.8, MariaDB 10.6 | Нижня межа майбутньої заяви сумісності |
| Наявний орієнтир Клубу | PHP 8.3, WP 7.1.1 з compose, WC 11.1.0 з README harness, MariaDB 11.4.5 | Середовище після перевірки доступності пакетів |
| Релізний | Актуальні підтримувані patch-версії на дату релізу, PHP 8.4 / MySQL 8.0 | Піни й digest записати перед прогонами; без floating latest |
| Режими | Classic / Blocks × HPOS on / off | Однакові фінансові правила |

Піни наявного harness не є доказом останнього релізу. Під час підготовки інтеграційних прогонів звірити доступність пакетів і зафіксувати patch-версії; перед етапом 9 — звірити з фактичним магазином. Старіші середовища не підключати мовчки. Етап 3 перевірений лише PHP syntax lint; сумісність WordPress/WooCommerce ще не підтверджена.

## Залежності наступних етапів

1. Етап 3: профілі/конфігурації, категорії, адміністративний аудит за FR01–03, FR10–11.
2. Етап 4: purchase storage, draft/finalize/lock та спільний серверний контракт.
3. До завершення етапу 5: закрити P01–P03 з аудиту; реалізувати WayForPay та фінансові винятки.
4. Етап 6: IBAN, рішення оператора, строки й виконання використовують той самий purchase lock.
5. Етапи 7–8: Blocks, сумісність, міграція й 65 критеріїв бази. №65 у PRD окремим абзацом — повноправний критерій.
6. Етап 9: C01–C15. Політика однієї послуги, Club-zero, LMS/CRM та фіскалізація лишаються окремими умовами запуску.

## Межі перевірки

Модель зіставлена з FR01–17 і критеріями PRD. Перевірені походження clone та незмінність PHP upstream. Схеми не є результатом виконання SQL. Тести, платіжні запити, production-операції та CI не запускалися.
